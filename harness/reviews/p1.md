## LOW P1-L01 — Permission assertion assumes a permissive umask

At tests/test_conformance.py line 148, the test requires exactly 0600. write_private deliberately creates mode 0600 subject to the caller's umask, and docs/IMPLEMENTATION correctly permits stricter permissions. An owner using a restrictive umask that removes owner-write or owner-read permission can receive a correctly more restrictive result while this assertion fails. This is test portability only and does not weaken output confidentiality.

Suggested correction — test the absence of group/other permissions and the expected mode after applying the captured umask, or scope the test to an explicitly controlled/restored umask. Add one restrictive-umask case if desired. No implementation change is necessary.
